## 1. 개발 방향

### 핵심 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 전송 수단 | **UDP 소켓**(Winsock2) 위에 직접 신뢰 전송 구현 | TCP 소켓을 쓰면 재전송이 숨겨져 과제 의미가 없음 |
| 프로그램 | `sender.exe`, `receiver.exe` 2개 (별도 프로세스, 같은 PC 127.0.0.1) | 과제 요구 |
| 동시성 | **단일 스레드 이벤트 루프**: `select()`(소켓, 타임아웃 ≤20ms) + `_kbhit()`(키 입력) 폴링 | Windows `select()`는 콘솔 입력을 못 기다림 → 짧은 타임아웃 후 키 확인. 락 불필요, 단계 실행 쉬움 |
| UI | **콘솔 TUI (ANSI 이스케이프)** — 윈도우/버퍼를 칸(cell) 막대로, 이벤트 로그 타임라인 | C만으로 가장 싸게 가독성 확보. GUI(GDI)는 위험 대비 이득 작음 |
| 단계 실행 | **송신기·수신기 모두** 키 입력(Space=다음 이벤트, A=자동(고정 지연), +/-=속도). 수신기는 패킷 도착마다 대기 | "단계별 확인" 요구 충족. 수신 측 버퍼 저장→중복 ACK 장면도 단계별로 설명 가능 |
| 손실 주입 | **수신기 입구**에서 폐기: 옵션 `--drop 300,500`(해당 seq의 첫 도착만 폐기) + `--loss N%`. 수신 화면에 "채널 손실 ✗" 표시. **송신기는 손실을 모름**(정상 전송으로만 표시, 타임아웃으로 인지) | 송신자가 손실을 모른다는 TCP 전제 유지. 시나리오 2 결정적 재현 |
| 시간 | 모든 시각을 `now_ms()` 한 함수로. **일시정지(Space 대기) 중에는 시계도 멈춤**(가상 시계) | 안 멈추면 단계 대기 중 재전송 타이머가 멋대로 만료됨 |
| 재전송 | 타임아웃 재전송만 구현. 3중복 ACK 빠른 재전송은 **넣지 않음** | 시나리오 2가 "타이머 만료 → 재전송"을 요구 |

### 프로토콜 (헤더는 크기 계산에서 제외, 데모용 최소 헤더)
- 패킷: `type(DATA/ACK/FIN) | seq/ack(u32) | len(u16) | payload ≤100B`
- 시작 seq = 100, 바이트 단위, `ACK(n)` = n-1까지 연속 수신
- 송신: base(가장 오래된 미확인) / nextseq, 윈도우 = **5 세그먼트(500B)** (상수 하나로 변경 가능)
- 타이머 1개: base 세그먼트용. base 전진 시 재시작, 모두 확인되면 정지, 만료 시 base만 재전송 후 재시작
- 수신: 윈도우 내 비순서 세그먼트 버퍼링, 연속 구간 병합 후 누적 ACK, 이미 받은 것/중복은 같은 ACK 재전송(= 중복 ACK 시연)
- 수신 윈도우 밖 세그먼트는 폐기(+현재 ACK 응답)

### 독창성(유사도 감점 회피) 방침
- 교재/예제식 구조(스레드 3개 + 뮤텍스, `struct packet` 배열) 안 씀 → **링 버퍼 + 단일 이벤트 루프 + 상태 머신** 설계
- 변수/함수명, 로그 문구, 화면 레이아웃 전부 직접 작성. AI/웹 예제 코드 복붙 금지, 내가 설명할 수 있는 코드만
- 차별화 요소(선택): 이벤트 로그를 `trace.log`로 저장 → 보고서 캡처/검증용, 시나리오 스크립트 파일(`scenario1.txt`)로 데모 자동 재생
- 파일 구성도 직접 정함(예: `wire.c`, `ring.c`, `tui.c`, `sender.c`, `receiver.c`) — 이름·분할을 남과 다르게
